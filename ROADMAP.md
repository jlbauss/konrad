## Next — beta → 1.0

*Clearing this gates 1.0: `konrad code` leaves preview, releases are tested and signed, and the document skills cover the common office formats.*

### `konrad code` out of preview

- [ ] `L` **Container per repo — terminal sessions join the repo's container (probed 2026-10-07: go).** Terminal sessions run inside the repo's `up` container (`<engine> exec -it … claude`, `claude --worktree` for parallel ones; `konrad code <url>` starts the container when it isn't up). That retires most per-session plumbing: the pid and session pick in container names, the `.sessions/<s>` worktrees, the per-session libpod `static_dir`/`volume_path` split, apple/container's per-session store volume (and `probe-shared-store.sh`), and PID-based reaping in `sweep_orphans`. Unchanged: the seal, the token, the volumes, the image.
  - **Costs:** one memory cap for all of a repo's sessions; an exec'd terminal session still ends with its terminal (`claude --continue` resumes it); setup runs once per repo instead of per session.
  - **`down` kills leftover exec clients first.** A frozen `exec -it` client blocks removal exactly like MR !22's `run -it` client (`given PID did not die within timeout`), so `down` and any sweep kill them before stopping.
  - **Sessions are directories, built by a konrad `WorktreeCreate` hook** in managed settings under `/etc/claude-code/` (out of the agent's reach): it creates `<sessions>/<name>/{<repo>,…}` as worktrees of every repo and prints the project's path; `WorktreeRemove` removes them, keeping any with work. Server-mode and `--worktree` sessions both call it. The hook input differs from the docs: `WorktreeCreate` gets only `name` and `cwd` (derive the toplevel with `git -C "$cwd" rev-parse --show-toplevel`, branch `worktree-<name>`); `WorktreeRemove` gets `worktree_path`.
  - **Absolute paths for sibling repos.** A `--worktree` session refuses git aimed at another directory by a relative or computed path (`git -C ../lib`); a literal absolute path works. So the hook writes a `CLAUDE.md` into the session dir naming each repo's absolute path. Trust follows the git repository, so each added repo needs its own trust, given in the setup run.
  - **Maintainer probes:** the whole shape on the host (`up`, a terminal session via `konrad code <url>`, a parallel one, a phone session, `down`); a real dropped SSH connection under an exec'd session; apple/container end to end.
  - **Docs:** ARCHITECTURE → konrad code (parallel sessions become worktrees in one container), README `konrad code` section.
- [ ] `M` **Per-repo config, one read-only agent binary (plan C, decided 2026-10-06).** `konrad-code-config` (`~/.config`: login, `settings.json` and its hooks, plugins, memory) and `konrad-code-tools` (`~/.local`: the `claude` binary and whatever the agent puts on `PATH`) are mounted read-write into every repo's sessions, so a compromised session can plant a hook, binary or wrapper that runs in the next project's session with that project's token, or swap the login (an accepted residual today; the weak link once a project holds several repos' tokens).
  - **Per repo:** `~/.config` and the rest of `~/.local` move into per-repo volumes (`konrad-code-<host>-<path>-config`, `-local`; `--profile` suffixes them). No seeding from the old shared volumes, which may be tampered with; the launch says they can be removed.
  - **Shared, read-only:** the binary (`~/.local/share/claude`; the `~/.local/bin/claude` symlink is made per run), mounted read-only through `ro_bind`'s per-engine choice, so it holds on apple/container too. Self-update off (`DISABLE_AUTOUPDATER=1`); konrad updates the binary in a short-lived container that mounts only the tools volume, on `konrad update` and at most daily on launch. The first-run install moves there.
  - **Login per repo (plan C).** Plan D, one `claude setup-token` shared read-only, is out: Remote Control needs a full-scope login ([docs](https://code.claude.com/docs/en/remote-control), read 2026-10-06), and a full login rewrites its credentials file, which a read-only mount refuses. Revisit only if a login per project proves a real burden.
  - **Constraints:** never set `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC` or `DISABLE_GROWTHBOOK` in a session (either turns Remote Control off). Worth a probe: whether managed settings under `/etc/claude-code/` can refuse hooks from anywhere else.
  - **Probes.** Baseline: a file written to `~/.config` and `~/.local/bin` in project A's session is visible in project B's. Then: neither is; a write under `~/.local/share/claude` fails on Podman and apple/container; a tool the agent installs persists in A, absent in B; the updater moves both projects to a new version and the in-session updater stays quiet; B asks for its own login, A's still works, and in each `claude --rc` reaches `/rc active` and receives a phone message (maintainer). Note which first-run questions a fresh config re-asks.
  - **Docs:** ARCHITECTURE → konrad code replaces the shared-volumes residual; README covers the login per project.
- [ ] `M` **Keep the forge token out of the agent's reach (evaluated 2026-10-07: realistic).** Today the token sits in the repo volume (`/workspace/.git-credentials`): a hijacked agent can send it anywhere, and it outlives the session until revoked. Instead a sidecar holds it: a stock reverse proxy (nginx or Caddy, configured rather than coded) on a network only it and the session share forwards *this project's* git smart-HTTP paths (`info/refs`, `git-upload-pack`, `git-receive-pack`) and adds the `Authorization` header. The clone's remote becomes the sidecar's plain-HTTP URL: no TLS interception, no CA in the image; push options and the `remote:` MR link pass through as part of the git protocol.
  - **Gains:** a leaked token stops being a residual and dies with the session; the proxy refuses every other path whatever the token's scopes, which makes `read_api` safe to grant (pass exactly the pipeline, job-log and MR-comment `GET`s; confidential issues stay unreachable).
  - **Unchanged:** during the session the agent can still push any branch and open MRs; review and the protected default branch stay the gate.
  - **Open:** one sidecar per repo container (so after container-per-repo); a port-scoped seal exemption for its address, like DNS's; the token prompt and expiry self-check move out of the agent container, the token into a volume only the sidecar mounts; one route per repo once there are several; a second VM on apple/container.
  - **Probe first:** clone, fetch and push with `merge_request.create` through the proxy, MR link back; any other project or API path refused; the token absent from everything the agent can read.
- [ ] `L` **Several repos per session.** A session holds one token for one repo, stored host-keyed (`https://oauth2:<token>@<host>` in git's `store` helper), so a second repo, a submodule's included, is refused, and work that spans repos (a shared contract repo, a consumer, a docs repo, possibly on another forge) ends with copying files by hand. Instead a project's sessions reach the repos the user added to it, each with its own token, cloned beside the project. **The gate is the human typing a token:** the agent can't create one, so it can't add a repo or raise its access, whatever text it reads (decided 2026-10-06). Builds on container-per-repo (the session layout), per-repo config and the token sidecar (both close residuals this widens).
  - **Grants per project:** `konrad code --with <url> <project-url>` asks once for that repo's token, adds a line to the project volume's credential file and clones it beside the project; later launches fetch it; `--without <url>` drops line and clone (refused while the clone holds unpushed commits). A grant holds for all the project's sessions until removed or revoked. One token per (project, repo) pair, so each is revocable alone. Relative URLs resolve against the project's, as in `.gitmodules`; other hosts work. The flags go before the project URL, since what follows it goes to `claude`.
  - **Credentials keyed by path:** `credential.useHttpPath`, every line keyed by its repo path, the project's own included. Probe that a line matches with and without `.git`; migrate the existing host-only line on the next start; `check_token` and the "`rm $CREDS`" hint become per repo.
  - **Access is the token's; konrad reports it.** *read* (Reporter + `read_repository`, or a deploy token) or *write* (Developer + `write_repository`), optionally `+ read_api` (pipelines, job logs, MR comments on private repos, but also confidential issues; the token question says so). konrad reads the scopes via the token self-lookup (a deploy token counts as read) and prints them in the startup lines and the prompt note (`lib: read · docs: write + read_api`); it enforces nothing on top. Every token gets the project token's self-check. No `api` scope: nothing here needs it.
  - **Protection check where the token can see it:** with `read_api`, read the default branch (`protected`, `developers_can_merge`, `can_push`; probe that they say what's needed) and warn when a write repo's is unprotected or the token could merge or push to it. Without `read_api`, stay silent.
  - **GitLab checklist per write repo** (README; matters most where merges deploy): default branch protected, merge and push Maintainers; token role Developer; deployment secrets as **Protected** CI variables, since every branch the bot pushes runs its own `.gitlab-ci.yml` with the unprotected ones; approvals aren't the gate, and `merge_request.merge_when_pipeline_succeeds` needs only `write_repository`, so the merge permission is. Project access tokens work on Free in a personal namespace (observed 2026-10-06), not in a Free group; deploy tokens are the read-only fallback.
  - **Layout and sync:** a session is a directory of sibling repos (the primary's clones, other sessions' worktrees), built by container-per-repo's hook. Existing session worktrees move once; a moved session's `--continue` starts fresh. Each launch fetches every repo and leaves working trees alone; a fresh clone or worktree runs `git submodule update --init`; a submodule without a token gets a one-line hint (`add it with --with <url>`), never a prompt, so no file in a repo can trigger a token question.
  - **Agent and docs:** the prompt note lists each repo with path and access, says pushes to read repos fail and branch switches need `git submodule update`, and how to reach a `read_api` token (`git credential fill`). README: `--with`/`--without`, access levels, the checklist. ARCHITECTURE: the gate, and the residuals (a read repo is an injection source for every write repo in the session; a private read repo's content can land on a public write repo's branch before review).
  - **Probes** (fixture: a project and a second repo on gitlab.git.nrw, a third on gitlab.com, each with its own tokens). Baseline: on `main` the second repo won't clone with the project token, and clones with its own. Then: `--with` asks once and clones, the next launch fetches silently; the cross-forge repo works; a read push is refused, a write push opens an MR; startup lines show read, write, `+ read_api`, and a deploy token as read; the protection warning fires on an unprotected fixture branch only; a pinned submodule is checked out with its token and hinted without; a parallel session gets the sibling worktrees with no question; `--without` refuses with an unpushed commit, removes line and clone without; a pre-change credential file still pushes; a line the agent adds pairing a repo with another repo's token is refused by the forge.
- [ ] `S` **IPv6 probe for the seal.** The seal's v6 routes are unprobed: no engine tested so far gives the container global IPv6 (rootless Podman can't resolve AAAA, apple/container can't connect over v6 even unsealed, the native-Linux default bridge hands out link-local only). Probe on a host whose Podman network has IPv6 enabled (or with pasta as the agent's network): `./scripts/probe-konrad-code.sh podman`; v6 targets that connect unsealed must fail sealed. Lifts README's "IPv6 networks aren't probe-verified yet" caveat.
- [ ] `S` **`konrad code up` across host reboots.** A reboot or engine restart ends the up container; `konrad code ls` and a terminal `konrad code` notice, but it takes a manual `konrad code up` to come back. A Podman quadlet (systemd user unit) or a launchd agent per up repo could restart it on boot. Weigh against the setup run's terminal: only the detached start would be automated, so a lost login would loop in the background.
- [ ] `S` **`konrad code` from Ghostty: `'xterm-ghostty': unknown terminal type`.** `do_code` passes the host's `TERM` through and the image has no terminfo for it, so `clear` and anything curses-based fails (seen 2026-10-01). Fall back to `xterm-256color` when `infocmp "$TERM"` fails in the entrypoint, or bake Ghostty's terminfo; check whether the `konrad` TUI has the same issue.

### The coworking agent

- [ ] `M` **Detachable `konrad` sessions — attach, detach, run in the background.** A `konrad` session lives exactly as long as its terminal (`run --rm -it`). Instead the opencode TUI runs under [dtach](https://github.com/crigler/dtach) in a detached container and a terminal is only a viewer; `run`, `connect` and `mcp-auth` stay plain `run --rm`. (`konrad code` got this through `up` and container-per-repo instead.)
  - **Shape (probed 2026-10-05):** a shared entrypoint helper beside `exec_as_node` runs the agent as `dtach -N <socket> -z` and passes the exit code through a file (dtach exits 1 regardless). dtach over tmux: tiny, no config, the terminal stays native; no screen replay. Attach via `exec -it` kills the session's other viewers first (a dropped terminal leaves a stale one), and nudges the size by a row: opencode repaints only on a real size change. The exit code travels over `exec`, since apple/container has neither `wait` nor an exit code in `inspect`.
  - **Session model:** containers `konrad-<workspace id>-<session>` with no pid; `--session X` attaches or starts; `attach`, `stop`, `ls`, `--background`; a launch notes sessions still running. The firewall proxy and its networks become per session, torn down by the attached terminal or the next launch's sweep; the scratch prune skips a dir with a live session. `stop` and the sweep kill leftover viewers first, since a frozen client blocks removal.
  - **Maintainer probes:** apple/container end to end (`run -d`, `exec -it`, the exit code over `exec`, stop); a real dropped SSH connection on the Linux host.
- [ ] `M` **Workspace snapshot / instant undo.** Before a run, snapshot `/workspace` via the fastest CoW available (`cp -Rc` on APFS, `cp --reflink=auto` on Btrfs/XFS, `cp -a` fallback) into a hidden `.konrad-undo/`; auto on `konrad run` unless `--no-snapshot`. `konrad undo` swaps back, `konrad commit-run` discards. Beats git here: survives a deleted `.git` and covers untracked and binary files.

### Security & sandboxing

- [ ] `M` **Evaluate micro VMs for `konrad code` on Linux, to take back what nesting relaxes.** On native Linux nesting turns off `no-new-privileges` and the `/proc` and `/sys` masks and allows kernel module auto-loading under `container_engine_t`, so a kernel bug is the whole wall between a hijacked agent and the host. A micro VM per session puts a guest kernel there, as macOS already has. Candidate: crun's libkrun handler (`--runtime krun`), keeping the Podman flow and volumes; also weigh Kata Containers. Probe: `/dev/kvm` on the hosts that matter, nested Podman and build speed in the guest, volumes over virtiofs, the seal and `host_ip_cidrs` from inside a guest, startup time, memory under `KONRAD_MEMORY`. If it holds: opt-in with a fallback where `/dev/kvm` is missing, then weigh making it the Linux default.
- [ ] `M` **Read-only root filesystem / writable-path minimization.** Run the agent with `--read-only` plus explicit tmpfs/writable mounts for what opencode needs. From the [2026-07-09 audit](SECURITY-AUDIT.md); referenced in ARCHITECTURE → State, secrets & isolation.
- [ ] `S` **Proxy bind + allow-list input hardening.** Bind tinyproxy to the internal-net interface instead of `0.0.0.0` (matters only on apple/container's shared `default` net); validate `allowed_hosts`/`--allow-host` entries against `^[A-Za-z0-9.*-]+$` before they become filter regex. Audit findings #7, #8.
- [ ] `S` **`merge-config.js` prototype-pollution guard.** Skip `__proto__`/`constructor`/`prototype` in `deepMerge`, with a fixture in the release-testing suite. Confirmed but low-impact (short-lived process, trusted layers). Audit finding #6.
- [ ] `S` **Enforce the offline model contract — `HF_HUB_OFFLINE=1`.** Set it (+ `TRANSFORMERS_OFFLINE=1`) in the final image so a missing model fails loud instead of attempting a fetch the proxy refuses; the build-time fetch stage is unaffected. Pair with a smoke assertion that loads every baked docling model offline. Lands after the RAG tokenizer is baked, which it would otherwise hard-block.
- [ ] `M` **Bake provider SDK adapters, dropping `registry.npmjs.org` from the egress floor.** opencode fetches non-bundled `@ai-sdk/*` adapters from npm on first use, the only reason npm is in the floor. Warm opencode's adapter cache at build time, keyed to the pinned opencode version (~5–20 MB; also sidesteps [opencode#21472](https://github.com/sst/opencode/issues/21472)). Verify first: the cache path, and that a pre-populated cache needs no registry re-check.
- [ ] `L` **Evaluate NVIDIA OpenShell as the sandbox backend.** [OpenShell](https://github.com/NVIDIA/OpenShell) (Apache-2.0) could replace konrad's own plumbing (the proxy sidecar, two-network topology, per-engine seal), not the product. Blockers as of 2026-09: 0.1.x churn, a heavier gateway control plane, no Podman driver on macOS, no plain workspace bind in microVM mode. Watch; re-evaluate at a stable release with a Podman/apple-container story.

## Blocked (externally)

- [ ] `S` **Retire the inline model-discovery probe when opencode ships native `/v1/models` discovery.** Upstream [opencode#27554](https://github.com/anomalyco/opencode/pull/27554) (open). Only scripted one-shots on macOS with the firewall are affected. Not worked around (an init wrapper + sentinel is real machinery for an upstream bug). Revisit on an apple/container bump: re-run the sealed test, or wire `--cidfile` + `container inspect` if it starts exposing the code.
- [ ] `S` **Clickable links in the TUI — blocked on opentui/opencode.** A click on a URL in the TUI does nothing: the TUI captures the mouse ([opencode#44442](https://github.com/anomalyco/opencode/issues/44442), open), and bare URLs carry no OSC 8 metadata ([#14966](https://github.com/anomalyco/opencode/issues/14966)).
